# T-010 — Configuração local por arquivo de ambiente

## Motivo da mudança

Para usar uma porta ou URL diferente dos padrões, era preciso configurar o terminal de quem iniciava a aplicação. O `.env.example` reúne os cinco valores aceitos em um modelo que cada pessoa pode copiar para `.env`. A API e o seed passam a usar a mesma configuração local entre sessões do terminal.

Nos testes, atribuir URLs e tempos a `process.env` alterava o estado compartilhado do processo. Uma instância podia herdar a configuração de um cenário anterior. Agora cada instância do Nest recebe explicitamente o banco de teste, a URL do servidor de moderação e os tempos daquele cenário.

## Critério de aceitação aprovado

- Ao iniciar a API com `npm start` ou `npm run start:dev`, o Node carrega o `.env` opcional. A CLI `npm run seed` lê a URL do banco pelo mesmo mecanismo.
- Se o terminal e o arquivo definirem a mesma variável, o valor do terminal prevalece. Se o arquivo estiver ausente, a aplicação pode iniciar com o ambiente do terminal ou os padrões locais.
- A suíte usa exclusivamente `anuncios_test` na porta 5433. Inicializar uma instância de teste preserva as variáveis de ambiente do processo.

## Evidências da implementação

- Antes da correção, `node --test test/setup.test.cjs` detectou que iniciar o Nest para consultar `GET /health` alterava `DATABASE_URL`.
- Depois da correção, `npm test` passou nos 12 testes. Na verificação de inicialização, `GET /health` retornou 200 com porta definida no arquivo, com porta sobrescrita pelo terminal e com configuração exclusiva do terminal.
- A CLI do seed tentou conectar ao banco inexistente indicado no arquivo. O nome apareceu no erro de conexão, confirmando a leitura de `DATABASE_URL`.
- `git check-ignore .env` confirmou que a configuração pessoal é ignorada pelo Git.

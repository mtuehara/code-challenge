# T-012 — Migrations fora do boot

> Nota posterior: a T-013 adicionou a sexta migration (`ReplaceListingIndexes1795881600000`). Esta spec registra o estado da T-012.

## Critério para revisão

Dado um banco vazio, quando o operador roda `npm run migration:run`, então as cinco migrations são aplicadas e o comando encerra. Quando a API sobe com `npm start` sem esse comando, ela **não** aplica migrations automaticamente. A suíte continua passando porque o helper de teste habilita migrations apenas no `anuncios_test`.

## Mudanças

- Migrations separadas em `src/infra/db/migrations/`, uma por arquivo, com nomes e timestamps preservados.
- `connectDatabase(url, { migrationsRun })` com default `false`; `database.ts` só importa e registra as migrations.
- `scripts/migrate.cjs` e `npm run migration:run` executam as pendentes e encerram.
- `createApp({ runMigrations })`; o helper de teste passa `runMigrations:true`.
- README, DECISIONS, AI_USAGE e test/README atualizados: `npm start`/`npm test` não migram o banco de desenvolvimento; `npm run migration:run` é a etapa explícita.

## Fora de escopo

Criar um container/init job de migration, rodar `down` de produção, ou adicionar um pipeline de CI. O comportamento de produção recomendado é executar `npm run migration:run` antes do rollout.

# T-006 — Listagem com paginação e filtro

## Critério para revisão

Dado um banco com três anúncios aprovados e um reprovado, quando o cliente faz `GET /ads?page=1&pageSize=2`, então recebe 200 com `{data, page, pageSize, total, totalPages}`, os dois aprovados mais novos na ordem `createdAt DESC, id DESC`, `total: 3` e `totalPages: 2`. Dado `category=esportes`, então recebe somente os aprovados da categoria. Dado `page=0`, `pageSize=101`, `page=abc` ou categoria inválida, então 400 com `details`, sem consultar o banco. Uma página além do fim devolve 200 com `data: []`.

## Mudanças

- `AdsRepository` em `src/ads/ads.repository.ts`: `create`, `save`, `findById`, `findApprovedPage({category, skip, take})`; o serviço não usa mais `DataSource` diretamente.
- `listaAdsQuerySchema` em `src/ads/ad.schema.ts`: `page`/`pageSize` com coerção e defaults 1/20, máximo 100, categoria opcional.
- `GET /ads` no controller, antes de `GET /:id`, com o mesmo `ZodValidationPipe`.
- `AdsService.list` monta `{data, page, pageSize, total, totalPages}` e usa `toAdResponse`.
- Migration `AddListingIndexes1795708800000`: índices parciais `(status, "createdAt" DESC, id DESC)` e `(status, category, "createdAt" DESC, id DESC)` para `status = 'approved'`.
- Teste `test/listing.test.cjs`; README, DECISIONS, AI_USAGE e test/README atualizados.
